# 村庄地质灾害综合整治GIS智能研判与多目标决策平台

本项目用于科研研判、方法验证和治理方案比选。系统把治理单元、工程措施准入、硬约束、四目标评价、精确枚举、离散NSGA-II、Pareto方案分析、空间协同和成果复核连接为一套可运行流程。

当前治理单元边界、道路、水系、承灾体和风险路径是平台演示数据，不代表现场实测成果；待标定参数需要结合规范、文献、工程案例、现场调查和专家评审复核。页面中的全寿命周期成本为方案比选阶段估算，不等同于施工预算。

## 主要功能

- 六个一级模块：项目总览、数据与单元、智能研判、方案比选、空间协同、成果管理。
- 两种使用模式：首次使用的“引导式研判”和参数已确认时的“快速分析”。
- 村庄级GIS主工作区：治理单元、道路、水系、承灾体、风险路径、在线街道底图和离线坐标网格。
- 地图、治理单元选择框、单元表格和代表方案之间的联动状态。
- 4个治理单元×8类候选措施形成32条唯一“单元—措施”准入判定记录。
- 精确枚举与离散NSGA-II两种求解方法，共用同一工程评价和约束函数。
- 两层算法验证：ZDT1、ZDT2、ZDT3、DTLZ2标准函数；精确枚举对照村庄工程案例。
- 四目标Pareto二维投影、代表方案热力图、NSGA-II超体积趋势和空间协同指标。
- 中文CSV、JSON、ZIP和可打印HTML科研分析报告。

## Windows启动

推荐解压到路径较短且具有写入权限的目录，例如`D:\village_decision_platform_v3`。

### 方法一：双击批处理文件

双击`start_windows.bat`。脚本按以下顺序检测Python：

1. 已存在的`.venv\Scripts\python.exe`；
2. `python`命令；
3. `py -3`命令。

首次启动会创建`.venv`并安装`requirements.txt`，随后打开`http://localhost:8501`。

### 方法二：PowerShell

在项目目录执行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\start_windows.ps1
```

### 方法三：命令行

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m streamlit run app.py
```

建议使用64位Python 3.10—3.12。首次安装依赖需要网络；之后平台计算不依赖外部API、数据库、MATLAB或GIS服务。在线街道底图不可用时，本地治理单元和离线坐标网格仍可工作。

## 引导式研判操作

1. 项目与研究区：填写项目、村庄和数据版本，确认数据性质。
2. 数据与治理单元：点击地图、表格或选择框查看单元完整属性；必要时导入CSV、GeoJSON和风险路径JSON。
3. 工程措施准入：核查32条准入判定、限制条件、剔除原因和专家复核事项。
4. 约束与求解设置：设置预算、稳定系数、安全得分、组合数量和求解算法。
5. 运行多目标优化：运行精确枚举或NSGA-II；只有本步真实计算成功后，结果步骤才可进入。
6. Pareto方案比选：比较五类代表方案。偏好权重只重选代表方案，不重新求解Pareto集。
7. 空间协同研判：检查物源控制、输移拦截、承灾体防护、完整路径覆盖和残余风险。
8. 复核与成果导出：核对场景标识、算法参数、专家复核事项和模型边界，导出成果。

“保存本步”和“下一步”基于真实校验结果；页面交互或刷新不会无故重置当前步骤。若模型输入变化，旧结果会标记为失效。仅调整代表方案偏好权重不触发重新优化。

## 快速分析操作

切换到“快速分析”，确认项目、村庄、求解方法和约束后点击“一键运行当前场景”。快速分析默认不执行多随机种子或标准函数验证，避免普通分析承担不必要的计算成本。

## 地图操作

- 点击治理单元面或中心选择点，右侧显示唯一编号、名称、类型、位置、岩土体、坡高、坡度、稳定系数、危险性、风险、承灾体、自动标签、准入/剔除措施、方案配置、治理前后指标和复核事项。
- 选中单元以橙色加粗边界和中心点突出；地图使用固定视图标识避免交互后无故回到区域尺度。
- 表格中当前单元置于首行；点击其他行可反向定位地图。选择框也与地图和详情共用`selected_unit`状态。
- 可切换治理前风险、治理后安全性、推荐措施和约束未满足单元。
- 风险路径采用“物源→输移→承灾体”语义。只有措施类型与路径环节相匹配才计为有效覆盖。
- OpenStreetMap仅称“在线街道底图”；离线模式不包含DEM或地形阴影。

## 数据替换与校验

平台支持治理单元CSV、措施库CSV、治理单元GeoJSON和风险路径JSON。导入时检查：

- 必填字段、类型、数值范围和缺失值；
- 治理单元编号唯一性；
- CSV与GeoJSON的`unit_id`集合一致；
- 风险路径的物源、输移、承灾体编号均存在；
- 措施编号唯一且等级、成本和得分范围有效。

真实GeoJSON应使用WGS84经纬度，并保证每个面要素的`properties.unit_id`与治理单元CSV完全一致。风险路径文件结构见`data/spatial_topology.json`。

## 精确枚举与NSGA-II

精确枚举逐一评价全部组合，适合当前4,356种组合的小案例，可提供完整、确定、可重复的Pareto基准。

离散NSGA-II将每个治理单元的准入组合索引编码为一个基因，通过约束支配、有限局部修复、锦标赛选择、离散交叉、变异、随机移民和精英保留近似搜索。默认60个体×25代，固定随机种子可复现。累计非支配档案的归一化超体积用于描述覆盖趋势，不再把“到人为理想点的距离”称作收敛指标。

当前小案例精确枚举明显更快；NSGA-II的价值主要在组合空间扩大后。平台不会在NSGA-II模式下默认运行完整精确枚举，只有用户主动启用算法对照时才运行基准。

## 两层算法验证

标准函数层使用ZDT1、ZDT2、ZDT3和DTLZ2，展示理论Pareto前沿、算法解集、IGD、GD、Spacing、Hypervolume及多随机种子均值与波动。它只验证算法基本机制。

工程案例层以精确枚举为基准，评价可行比例、非法组合、硬约束满足率、完全/近似覆盖率、支配比例、漏解、目标范围覆盖、运行时间、唯一评价数量、搜索空间占比和跨种子稳定性。它验证离散编码、约束、修复和工程评价耦合。

## 安全、成本与空间协同口径

- 安全得分由稳定性分项和灾害链控制分项构成；0—100分阈值为待标定口径。
- 稳定系数下限防止力学不安全；安全得分下限防止综合分掩盖灾害链短板。
- 谷坊坝和柔性拦挡结构主要降低输移或冲击后果，不直接提高上游物源斜坡稳定系数。
- 不治理方案不再因“零成本”获得虚高的可持续性和韧性。
- 全寿命周期成本包含建设、维护折现、施工组织和地形修正；仍未建立正式工程量清单和施工预算模型。
- 空间协同当前用于结果解释和代表方案复核，尚未作为NSGA-II独立优化目标。

## 常见问题

### 没有Python或无法创建虚拟环境

安装64位Python 3.10—3.12并勾选“Add Python to PATH”；确认项目目录可写。

### 依赖安装失败

检查网络或代理，然后执行：

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 地图底图空白

切换为“离线坐标网格”。本地GeoJSON、风险路径、表格、求解与导出不依赖在线底图。

### 结果突然标记失效

治理单元、措施、预算、硬约束、NSGA-II参数或求解方法发生变化后必须重新计算。仅修改代表方案偏好权重不要求重算。

### NSGA-II比精确枚举慢

这是当前4,356种组合小案例的预期现象。使用精确枚举作为默认求解；当治理单元和组合规模显著扩大时再使用NSGA-II。
