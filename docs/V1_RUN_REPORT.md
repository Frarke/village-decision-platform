# V1 完整运行与交付报告

日期：2026-09-15；项目：嵌入多目标优化的村庄地质灾害综合整治工程技术智能研判与决策。V1为本轮空间业务闭环集成版本，保留原V4方法内核。实现基线 `6b3fda9`，分支 `codex/v1-system-integration`。

## 1. 最初项目状态

仓库工作区干净，已有独立集成分支和检查点。科技报告、任务说明、中期PPT、MATLAB原型、Python模型、Streamlit工作台、示例数据及历史输出齐全。原始材料位于 `references_private`，未修改。基线实际测试为68项通过，旧STATUS写的57项不是当前基线。

## 2. 原系统已经实现的内容

八类措施、入库和多标签规则、措施准入、互斥/主控/双措施组合、四目标、地形修正、预算/安全底线、确定性精确枚举、离散NSGA-II、五类代表方案、标准函数测试、原工作台和表格/JSON/HTML导出。当前基线代码已共用 `evaluate_village_scheme`，区域关键路径覆盖已参与村域韧性；不能沿用旧文档声称“尚未进入优化”。

## 3. 原系统主要问题与审计证据

主要断点是从预定义治理单元开始，没有从基础空间评价成果生成治理区域/单元；没有独立API；正式展示与开发中间量混杂。直接调用评价器可绕过准入/组合校验，零风险权重静默均分，单元路径数字与topology分离，输入散列未纳入topology。部分文档及A19参数条目仍写旧经济性/后置协同。

已实际解析科技报告正文与表5-1～5-3、任务说明、六页PPT文本，查看两张参考界面图片，检查MATLAB目标函数/主程序/内核/批处理与CSV、MAT变量，检查全部业务文件格式及内容。文件级清单、大小、SHA256和解析方式见 `V1_AUDIT_INVENTORY.csv`。环境目录、Git对象和缓存未作为科研数据分析。MAT中包括500×13末代染色体、100500×13累计解和metrics；未发现可执行MATLAB环境，未重新运行MATLAB。其实际DTLZ2原型与报告声称ZDT1验证之间的可复现证据差异保留，未挪作工程依据。

## 4. 最终输入

`village + spatial_layers + engineering_profiles + unit_risk_weights + topology + configuration`，可选外部措施库。提供村界/CRS、基本空间评价面或栅格、工程调查属性、显式权重和路径。支持vector、raster_grid、多波段GeoTIFF；本地文件层支持GeoJSON、CSV/WKT、XLSX/WKT。检查CRS、几何有效性、重叠、编号、字段、值域、同网格和NoData。

实际项目文件中未发现真实TIF/Shapefile/调查GIS/易发性等评价成果。PNG/JPG只是界面参考，不参与GIS运算。新增模拟评价网格与真实接口一致，不要求上游提供已经划好的单元。完整输入规范见 `V1_API.md`。

## 5. 最终输出

返回重点区域、治理单元（geometry/属性/候选措施/权重/溯源）、完整本次非劣集、五类代表方案、每类方案GeoJSON、四目标/费用/前后指标、路径覆盖、约束、真实历史和provenance。输出保存于 `output/v1`，包括请求快照、result.json、交互map.html、GeoJSON、CSV、成果ZIP、对照记录及日志。

## 6. 治理区域如何确定

采用科技报告表5-1的逻辑：风险等级≥3，或承灾体距离≤100米，或已有隐患/风险区识别标记，或重点关注标记。阈值集中于 `SpatialConfig`，保持报告默认值。易发性/易损性用于统计解释，不额外编造治理阈值或四目标公式。本例144像元中24个命中，重点面积240,000平方米（24公顷）。

## 7. 治理单元如何生成

裁剪村界，在同一工程调查属性区内识别共边连续斑块；角点相接保持独立；MultiPolygon内分离斑块也独立参与识别。按最小面积过滤，允许配置邻近合并及大斑块网格拆分。邻近合并不以缓冲区虚增面积。按属性区与空间位置确定性排序编号U01…；源片区保留。默认最小面积100平方米、合并距离0米、不开启拆分，均为V1暂定空间细则。本例自动形成4个单元，每个6公顷，每单元由6个基础像元组成。

## 8. 单元属性

自动属性：编号、geometry、面积、质心、来源像元、风险/危险性最大等级、最近承灾体距离、坡度均值/最大值、易发性均值/最大值、易损性均值/最大值、识别原因。措施筛选使用最大坡度等保守统计（暂定），工程调查字段只保留原模型实际需要的降雨、坡高、汇水、沟谷、施工空间、FS0、Krain和排水/锚固/滑面/可达性。风险权重显式赋值后归一化，路径数由同一topology提取。

## 9. 工程措施如何筛选

复用 `screen_all/screen_measure` 的8类措施与报告规则：截排水工程、灌草种植、植被混凝土、格构锚固、挡墙工程、抗滑桩、谷坊坝、柔性拦挡结构。每个单元形成准入/排除理由、候选措施和合法组合；允许同单元多措施，默认最多2项，保留互斥与主控要求。费用和效果复用原库并标记待标定；没有重建一套不相容措施体系。

## 10. 四目标与统一评价

保留 METHOD_SPEC 中正式公式、指标权重及目标方向，四目标均0～100、越大越好。经济性仅LCI/SC，货币总成本按单元相加用于预算与输出。精确与NSGA-II均使用相同候选组合编码、`evaluate_village_scheme`、准入/组合/预算/安全约束。入口不修复、不替换候选；非法方案返回约束原因。原待标定FS映射、成本地形修正等迁至 `EvaluationParameters`，默认值保持基线，完整展开并导出。

## 11. 区域协同的位置

在每个候选方案评价内部：单元评价→topology路径覆盖→区域聚合→形成四目标→约束→非劣比较。区域安全仍为 `0.6min + 0.4风险加权均值`；经济/可持续按风险权重；统一关键路径覆盖进入村域韧性。单元局部覆盖统计自身承担环节，村域统计完整路径，二者源自同一批路径记录。结果页回显评价结果，非首次评分；协同不是第五目标。修改topology会改变输入标识，必要时改变四目标与前沿。

## 12. NSGA-II实际运行情况

本例种群60、25代、交叉0.90、变异0.20、固定种子42；记录第0代初始化至第25代，共26条真实历史。主运行评价1,946个唯一方案，找到295个可行方案及16个非劣方案。原非支配排序、拥挤距离、锦标赛、离散交叉/变异、局部修复、精英和移民机制保留。没有模拟进度或固定解数。

## 14. 最终页面及实际交互

正式页面以地图为核心，显示村界、按措施着色的单元、当前单元高亮、措施图例、单元风险与前后安全/韧性、费用；五类代表方案同步切换。提供KPI、四目标雷达、Pareto投影、措施组成和完整非劣表。调试模式展示原始属性、候选、真实历史和依据。

实际浏览器验证：点击U02、U03多边形后选择框和详情切换；经济优先成本323.5万元、路径完整覆盖0%，韧性优先成本486.7万元、覆盖66.7%，地图及指标相应改变；离线HTML也完成单元点击和方案切换。上传 `acceptance_upload.json` 后研究区名称变为“上传验证研究区（模拟数据）”、预算400万元，原结果失效；实际求解后综合均衡方案约339.2万元，显示了变化后的配置。不是只用事件模拟代替浏览器验收。正式页面初始地图视野偏小，已根据实看调整。

## 19. 暂定与待标定参数

自动化覆盖空间转换/NoData/连通/角接触/多面/过滤/拆分/面积/非法几何与重叠、直接非法方案、权重与路径、双求解器同评/复现、服务与接口、地图图表和导出、页面运行/切换/失效及上传前阻断。最终完整pytest结果为 **105项通过、1条第三方依赖弃用提示，用时42.19秒**；包含本轮新增37项测试。39个Python文件的语法解析、8个运行模块导入检查通过。

## 22. 当前仍未解决的限制

没有真实场景工程验证；Shapefile直读、多文件栅格自动对齐/重采样、多图层自动叠置、DEM水文路径、权重自动公式、工程量清单和生产鉴权/异步队列尚未接入。当前输入上限10,000基础片区/像元、64生成单元，精确枚举上限200,000组合。NoData区域被明确排除，因此不应把有限覆盖下的结果当作全村风险排查结论。用户改变分区后须复核显式权重和路径编号。原工作台仅作为回退/开发入口。

## 23. 如何启动

```powershell
.venv_codex\Scripts\python.exe -m pip install -r requirements.txt
.venv_codex\Scripts\python.exe -m streamlit run v1_app.py --server.address 127.0.0.1 --server.port 8517
.venv_codex\Scripts\python.exe -m uvicorn api:app --host 127.0.0.1 --port 8017
```

在两个终端分别启动页面与API；直接页面不依赖API进程。也可使用Windows启动脚本，或安装依赖后的自有Python3.12环境。服务仅绑定本地回环地址。

## 24. 如何运行完整流程

页面选择示例或上传规范JSON→查看识别统计→运行综合研判→切换方案/查看单元→导出。真实数据接入可先 `/prepare` 取得单元编号，再明确权重和路径后 `/optimize`。

批处理：`.venv_codex\Scripts\python.exe -X utf8 run_v1.py --compare`。其他项目用 `--input 项目.json --output 新输出目录`。验证：`.venv_codex\Scripts\python.exe -m pytest -q -p no:cacheprovider`。

## 25. 如何查看成果与下一步

直接打开 `output/v1/map.html` 可离线切换五方案、点击单元；打开 `decision_results.zip` 查看完整快照；`result.json` 为平台集成输出，`solver_comparison.csv`为三种子对照，`validation.json`保存参数与实测运行时间。正式在线页面为 `http://127.0.0.1:8517`，API文档为 `http://127.0.0.1:8017/docs`。
